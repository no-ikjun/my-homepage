GIST 챗봇은 학사 공지, 학사 편람, 신입생 안내 자료처럼 흩어진 공식 문서를 검색해서 답하는 서비스입니다. 처음 버전은 NestJS 백엔드 하나에 문서 검색과 답변 생성이 전부 들어 있었습니다. 동작은 했지만, 검색 방식을 바꿔볼 때마다 답변 서버 전체를 다시 배포해야 했고, 실험 한 번에 반나절이 걸렸습니다.

이 글은 그 구조를 **MCP(Model Context Protocol)** 기반으로 다시 짜면서 내렸던 판단과, 지금 돌아보면 다르게 했을 것들을 정리한 기록입니다.

## 왜 검색을 분리했나

문제는 결합도였습니다. 답변 생성 로직과 검색 로직이 같은 프로세스 안에서 같은 타입을 공유하다 보니, chunking 크기 하나를 바꾸는 실험도 "안전한 배포"의 대상이 됐습니다.

> 실험 비용이 높으면 실험을 안 하게 되고, 실험을 안 하면 품질은 그 자리에 멈춥니다.

MCP는 도구를 별도 서버로 두고 표준화된 방식으로 호출하는 프로토콜이라, 검색을 "챗봇이 쓰는 도구 하나"로 바라보게 해 줍니다. 구조는 이렇게 바뀌었습니다.

| 구성 요소 | 이전 | 이후 |
| --- | --- | --- |
| 문서 검색 | 백엔드 내부 모듈 | 독립 MCP 서버 |
| 답변 생성 | 백엔드 | 백엔드 (MCP 클라이언트) |
| 새 데이터 소스 추가 | 백엔드 수정 + 배포 | MCP 서버에 도구 하나 추가 |

## 도구 인터페이스를 좁게 잡기

처음에는 검색 서버에 `search`, `search_by_category`, `search_recent`처럼 도구를 여럿 노출했습니다. 모델이 상황에 맞는 도구를 고르길 기대했는데, 실제로는 비슷한 도구 사이에서 헤매는 경우가 더 많았습니다.

결국 도구는 하나로 줄이고 인자를 넓혔습니다.

```ts
server.tool(
  "search_documents",
  {
    query: z.string(),
    category: z.enum(["notice", "handbook", "orientation"]).optional(),
    limit: z.number().int().min(1).max(10).default(5),
  },
  async ({ query, category, limit }) => {
    const hits = await index.search(query, { category, limit });
    return { content: hits.map(toTextBlock) };
  },
);
```

도구가 하나면 프롬프트에서 설명할 것도 하나뿐이고, 로그를 볼 때도 "어떤 도구를 골랐나"가 아니라 "어떤 인자를 넘겼나"만 보면 됩니다.

## chunking은 문서 종류마다 달라야 했다

- **학사 공지**는 짧고 날짜가 중요합니다. 문서 하나를 통째로 chunk 하나로 두고, 제목과 게시일을 본문 앞에 붙였습니다.
- **학사 편람**은 길고 조항 단위로 참조됩니다. 조·항 경계를 기준으로 자르고, 상위 장 제목을 각 chunk에 접두어로 넣었습니다.
- **신입생 안내 자료**는 표가 많습니다. 표는 행 단위로 풀어서 "항목: 값" 문장으로 바꾼 뒤 저장했습니다.

한 가지 규칙으로 통일하려던 초기 시도는 편람 답변의 정확도를 눈에 띄게 떨어뜨렸습니다. 문서 종류별로 나눈 뒤에야 "몇 조에 근거한 답"이 제대로 나오기 시작했습니다.

## 지금 돌아보면

1. 평가 세트를 먼저 만들었어야 했습니다. 질문 40개와 기대 답변을 정리한 뒤로는 구조 변경의 효과를 숫자로 볼 수 있었는데, 그 전까지는 감으로 판단했습니다.
2. 응답 속도는 구조가 아니라 검색 인덱스 쪽 문제였습니다. MCP로 나눈 뒤 오히려 호출이 한 단계 늘었지만, 인덱스를 바꾸자 전체 지연이 절반으로 줄었습니다.
3. iframe 위젯으로 배포한 결정은 옳았습니다. 학내 다른 서비스가 태그 하나로 챗봇을 붙일 수 있게 되면서 실제 사용처가 늘었습니다.

코드는 [chatbot-mcp](https://github.com/gsainfoteam/chatbot-mcp)와 [chatbot-be](https://github.com/gsainfoteam/chatbot-be) 저장소에 있습니다. 비슷한 구조를 고민 중이라면 `search_documents` 도구 하나에서 시작해 보길 권합니다.
